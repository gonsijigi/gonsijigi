## 0. 핵심 그림 — 3가지 모드

이 앱은 **외부 의존이 없어도 죽지 않게** 설계돼 있어서, 준비된 만큼만 켜도 됩니다.

| 모드 | 필요한 것 | 되는 것 | 용도 |
|---|---|---|---|
| **① 폴백** | 아무것도 (서버만) | 화면 전부, 가드레일, mock 공시, 폴백 해석 | 그냥 구경, UI 작업 |
| **② 리플레이** | 서버 + `REPLAY_MODE=true` | ①에 더해 **알림 폴링→HITL 전체 흐름**을 준비된 공시로 재생 | **발표 연습·리허설 (추천)** |
| **③ 풀스택 라이브** | 서버 + Docker(pgvector) + Ollama + DART 키 | 실제 오늘 공시 + RAG 과거 유사 공시 근거 + LLM 해석 | 실전 시연 |

## 1. 켜기

### 1-1. (풀스택일 때만) 인프라 확인 — 명령 2개

```bash
# pgvector DB — "Up ..."이 보이면 이미 켜져 있는 것 (보통 켜져 있음)
docker ps
# 안 떠 있으면:
docker compose -f infra/docker-compose.yml up -d db

# Ollama 모델 확인 — bge-m3(임베딩·필수), gemma3n:e4b(LLM·선택)가 보여야 함
ollama list
```

### 1-2. 서버 켜기 — 명령 2개

```bash
source .venv/bin/activate

# 리플레이 모드(발표 연습, 추천):
REPLAY_MODE=true uvicorn app.main:app --port 8010

# 라이브 모드(실제 오늘 공시):
uvicorn app.main:app --port 8010
```

- 포트 8000이 이미 쓰이고 있으면 위처럼 `--port 8010` 등으로 바꾸면 됨.
- `.env`에 `REPLAY_MODE=true`를 적어둬도 되지만, 위처럼 **명령 앞에 붙이는 쪽이 안전** (끄는 걸 잊지 않음).

### 1-3. 접속

브라우저에서 **http://127.0.0.1:8010/** ← 끝.

## 2. 화면 지도 — 뭐가 있고 각각 뭐 하는 곳인가

| URL | 이름 | 뭐 하는 곳 | 시연 포인트 |
|---|---|---|---|
| `/` | **홈 (사용자)** | 좌: 대화창(SSE 스트리밍) · 우: **🔔 알림 패널(LIVE)** + "새 공시 확인" 버튼 | 질문→근거 붙은 답변, 알림 실시간 등장, 무의미 입력 되묻기. 알림은 **필수 5종만** 선별 — `[수주]`·`[유상증자]` 뱃지 + 유상증자 자금 목적 라벨 |
| `/watchlist/` | **관심종목 (사용자)** | 종목 등록/삭제 (파일 저장, 서버 꺼도 유지) | 여기 등록한 종목이 알림 폴링 대상이 됨 |
| `/admin/` | **검토 큐 (관리자)** | 고위험 공시가 사람 승인을 기다리는 곳. 승인/반려 버튼, AI 해석, 카드 미리보기, DART 원문 링크 | **HITL 장면의 주인공** |
| `/admin/inbox` | **알림함 (관리자 뷰)** | 승인되어 발송된 알림 목록 (홈 패널과 같은 데이터) | 승인→발송 완결 확인 |
| `/docs` | API 문서 | FastAPI 자동 문서 | 질문 들어오면 보너스용 |

- 사용자 화면(`/`, `/watchlist/`) 상단 네비엔 **admin 링크가 안 보입니다**(뷰 분리). 관리자 화면은 URL로 직접 진입.
- 알림 패널은 5초마다 자동 갱신(`GET /notifications`). "새 공시 확인" 버튼 = `POST /poll` 수동 폴링 1회.

## 3. 검증된 5분 데모 코스 (리플레이 모드 — **진짜 공시 데이터**)

리플레이 샘플은 이제 **실제 DART 공시**(진짜 접수번호)라서 **원문 링크가 실제로 열립니다**.
발표 전날/당일 데이터로 갱신하려면 (DART 1회 호출):

```bash
python scripts/prepare_replay.py            # 오늘 날짜 기준 재생성 (고위험+일반 자동 큐레이션)
```

`REPLAY_MODE=true`로 서버를 켠 상태에서 (검증 완료 흐름):

1. **관심종목 등록** — `/watchlist/`에서 샘플에 있는 종목 등록 (샘플 재생성 시 콘솔에 목록이 찍힘)
   - 예 (2026-07-08자 샘플 기준): `006740 블루산업개발`(⚠️유상증자 → HITL용) + `043260 성호전자`(일반)
   - 기본 시드 3종목(삼성전자 등)은 당일 샘플에 없으면 폴링에 안 잡히는 게 정상
2. **홈에서 "새 공시 확인" 클릭** — **일반 공시는 알림 패널에 바로**, 유상증자는 **안 뜸** (여기가 포인트!)
3. **`/admin/` 접속** — 유상증자 건이 위험 키워드 태그와 함께 대기 중. AI 해석·카드 미리보기 펼쳐 보이기
4. **[승인] 클릭** → 홈으로 돌아오면 알림 패널에 등장 (**HITL 완결**)
   - 알림 카드 클릭 → 해석 + **DART 원문 링크가 진짜로 열림** (근거 시연의 하이라이트)
5. **대화 시연** (홈 입력창):
   - `"오늘 내 종목 공시 뭐 있었어?"` → 근거 붙은 해석 스트리밍 (풀스택이면 [유형]/[사실]/[해석 참고] 구조 + RAG 과거 유사 공시)
   - `"그래서 지금 팔까?"` → **가드레일 정중 거절**
   - `"ㅁㄴㅇㄹ"` → **"질문을 이해하지 못했어요..."** 되묻기 (LLM 없이 즉시 — 파싱 노드)
   - `"삼성전자 유상증자 있어?"` → 특정 종목·키워드만 골라 조회 (질문 파싱 시연)

### ⚠️ 리허설 후 반드시 서버 재시작!
폴러는 "이미 본 공시"를 메모리에 기억해서(`_seen`), 리허설에서 "새 공시 확인"을 누르면 **본 시연 때 신규 0건**이 됩니다. 알림함·검토 큐도 메모리라, **서버 재시작 = 깨끗한 무대 리셋**. 발표 직전 재시작이 곧 초기화입니다.

## 5. RAG 근거(과거 유사 공시)까지 보려면 — 풀스택

RAG 코퍼스는 **각자 로컬 DB에 적재**해야 합니다 (팀원이 적재한 건 팀원 컴퓨터에만 있음):

```bash
# 1) 인프라: docker db + ollama (1-1 참고)
# 2) 적재 (DART 키 필요, 1회 ~수분):
python -m app.rag.ingest --clear
# 3) 적재 확인:
python tests/verify_rag.py
```

이후 대화 답변에 `[참고: 과거 유사 공시]` 근거가 붙습니다. **적재를 안 해도 앱은 정상 동작**(근거만 빠짐).

## 7. 자주 막히는 것

| 증상 | 원인 | 해결 |
|---|---|---|
| `address already in use` | 포트 점유 | `--port 8010` (또는 8011, 8012...) |
| 리허설했더니 "새 공시 확인"이 0건 | 폴러가 이미 본 공시 기억(`_seen`) | **서버 재시작** (§3 경고 참고) |
| 알림함/검토 큐가 비어 있음 | 인메모리 저장 — 재시작하면 초기화(의도됨) | 다시 "새 공시 확인"부터 |
| 답변이 "(LLM 연결 실패 — 원문 요약으로 대체)" | Ollama/vLLM 미기동 | 폴백 정상 동작 중. LLM 원하면 `ollama list`로 gemma3n:e4b 확인 |
| 라이브 모드인데 mock 회사가 나옴 | DART 키 없음/한도 초과(020)/`corp_map.json` 없음 | 콘솔 경고 확인 → 리플레이 모드로 전환하거나 키 확인 |
| "삼성SDS"는 되는데 다른 종목명 인식 안 됨 | `data/corp_names.json` 없어 기본 3종목+별칭만 매칭 | 재생성: `python -c "import os;from dotenv import load_dotenv;load_dotenv();from app.tools.dart import build_corp_map;build_corp_map(os.environ['DART_API_KEY'])"` |
| 발표 아침 점검을 한 번에 | — | `python scripts/demo_morning.py` (인프라 점검+오늘 공시 스캔) |
