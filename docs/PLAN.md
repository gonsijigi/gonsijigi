## 0. 딱 하나의 목표: "발표에서 보여줄 5장면"

계획은 기능 목록이 아니라 **데모 장면에서 역산**합니다. 아래 5장면이 실제로 돌아가면 성공, 나머지는 전부 로드맵입니다.

1. **알림 도착** — 실제 DART 공시가 5분 안에 해석되어 화면에 뜬다
2. **대화 질의** — "오늘 내 종목 공시 뭐 있었어?"에 근거(접수번호 링크) 붙은 답이 스트리밍된다
3. **가드레일** — "그래서 팔까?"를 정중히 거절한다
4. **HITL** — 유상증자 건이 관리자 검토 화면에 멈춰 있고, 승인하면 발송된다
5. **폴백** — .env를 비우고 재실행해도 죽지 않는다 ("LLM이 죽어도 서비스는 산다")

## 1. 3대 원칙

- **세로 슬라이스**: 케이크를 층별로 굽지 말고, 한 조각을 끝까지 잘라 먼저 맛본다 — 수집→해석→알림 한 줄을 D1에 관통시키고 살을 붙인다.
- **매일 저녁 '데모 가능한 상태'**: 하루가 끝날 때 항상 돌아가는 버전이 있어야 한다. 발표 전날 밤 통합은 금지.
- **시간 도둑 3대장 회피**: ①공시 원문 XML 파싱 지옥 ②인프라 욕심(K8s 실배포) ③UI 꾸미기. 셋 다 빠지면 하루가 증발한다.
