## 1. 슬라이드 멘트 (14장)

**1. 표지** — "저희는 '공시지기'를 만들었습니다. 공시가 게시되고 5분 안에, 근거가 붙은 해석이 도착합니다. 그리고 매매 판단은 하지 않습니다 — 이 한 문장이 제품의 전부입니다."

**2. 문제(김개미)** — "32세 직장인 투자자 김개미는 오늘도 공시를 놓쳤습니다. 공시 게시에서 이해까지 반나절에서 이틀. 정보는 공개돼 있는데, 소화할 시간과 지식은 공평하지 않습니다. 1,400만 개인투자자의 흔한 하루입니다."

**3. 산업 특성** — "금융투자 산업의 드문 장점은 데이터가 이미 열려 있다는 겁니다. DART OpenAPI로 공시 목록과 원문을 무료로 가져올 수 있습니다. 데이터 접근이 장벽인 다른 산업과 달리, 여기선 Delivery의 첫 관문이 공짜로 열립니다."

**4. AI 도입 현황** — "기존 서비스들은 시장 단위 브리핑이거나, 내 종목 얘기가 아니거나, 근거 링크가 없습니다. 공시지기의 차별점은 '내 종목 + 원문 근거 + 5분 내'입니다."

**5. 후보 10개** — "후보 10개를 데이터 접근성, 규제 리스크, 페인포인트 직결성 세 필터로 걸렀습니다."

**6. MVP 선정** — "공시지기를 고른 근거 네 가지 — 데이터 개방, 규제선을 그을 수 있음, 페인포인트 직격, 그리고 수업에서 배운 기술로 끝까지 만들 수 있다는 것."

**7. TO-BE 시나리오** — "공시 게시 5분 뒤 김개미 화면입니다. 이따 데모에서 이 화면이 실제로 도는 걸 보여드리겠습니다."

**8. 아키텍처** — "그림의 박스가 곧 저장소 폴더입니다 — 다이어그램과 코드가 1:1이라 설계-구현 추적이 바로 됩니다. 오른쪽 태그 중 K8s만 로드맵 선언이고 나머지는 전부 동작합니다. 안 한 것에 선을 긋는 것도 설계라고 생각했습니다."
› *[수업→적용→왜]* "LangGraph를 체인이 아니라 그래프로 쓴 이유: '가드레일이 통과시켜야만 다음 단계'라는 조건부 흐름과, 고위험 건이 사람을 기다리는 HITL 대기는 그래프 노드로만 자연스럽게 표현됩니다. 조건부 분기 3개(차단/되묻기/고위험)에 checkpointer와 thread_id로 사용자별 맥락까지 — 수업에서 배운 요소 그대로입니다."

**9. RAG** — "오픈북 시험 원칙 — 근거에 없는 말은 하지 않는다. 수업 PGVector 실습을 재활용해 실제 공시 원문 159청크를 적재했고, bge-m3 1024차원 임베딩에 거리 0.5 임계값으로 무관한 근거를 자릅니다. 실측 검색 거리 0.30~0.36. 설계서에 있던 BM25 앙상블은 로드맵으로 남겼습니다 — 타임박스를 정해두고 벡터 단독으로 먼저 완성하는 게 Delivery 판단이었습니다."

**10. 안전장치** — "안전은 프롬프트로 부탁하지 않고 코드로 강제합니다. 출처 링크와 면책 문구는 notify_format 코드가 붙이고, 발송 직전 redact가 개인정보·키를 마스킹하며, 이 세 불변은 CI가 매 PR마다 검증합니다. 공시 원문은 외부 데이터라 스포트라이팅 경계로 격리해 간접 인젝션을 막습니다."

**11. 확장 설계** — "Handoff와 A2A는 로드맵입니다 — 오늘은 단일 에이전트를 끝까지 완성하는 데 집중했습니다."

**12. 평가 지표** — "배포는 시작입니다. 알림 지연 P95 5분, 출처 포함률 100%, 가드레일 차단 95% — 숫자로 관리할 겁니다."

**13. 기대 효과와 한계 (다크)** — "공시 파악 30~40분이 알림 확인 1~2분이 됩니다. 한계도 분명합니다 — 해석은 참고 정보일 뿐이고, 소형 모델의 해석 품질은 HITL과 평가로 보완합니다. …공시가 게시되고 5분, 김개미의 퇴근길이 달라집니다. **이제 직접 보여드리겠습니다.**"

## 2. 라이브 데모 대본 (~3분, 검증된 실제 출력 기준)

> 창① 홈(`/`) · 창② 관리자(`/admin/`) 미리 열어둠. 관심종목: 삼성전자·SK하이닉스(+아침 스캔에서 고른 ⚠️종목).

**장면 A — 근거 붙은 해석 (삼성전자)** *(40초)*
- 입력: `삼성전자 최근 공시 해석해줘`
- 예상 출력: 자기주식처분결정(7/7) — **[유형]/[사실]/[해석 참고]** 구조 + 원문 링크 + 면책
- 멘트: "방금 나온 답을 보시면 '사실'과 '해석 참고'가 분리돼 있습니다. 단정하지 않는다는 원칙이 출력 구조 자체에 강제돼 있고, 모든 답엔 DART 원문 링크가 붙습니다. **(링크 클릭 → 진짜 원문 열림)** 이 근거는 프롬프트가 아니라 코드가 붙입니다."

**장면 B — 고위험 인터셉트, HITL (SK하이닉스)** *(60초)* ← **하이라이트**
- 입력: `SK하이닉스 최근 공시 해석해줘`
- 예상 출력: `[컴플라이언스 검토 대기 — 승인 후 발송됩니다]` + 유상증자결정(7/6) 카드
- 멘트: "요새 핫한 SK하이닉스, 실제로 지난주 유상증자를 결정했습니다. 보세요 — 시스템이 해석은 만들었지만 **바로 내보내지 않고 멈췄습니다.** 유상증자는 고위험 공시라서요."
- **창② 전환** → 검토 큐에 SK하이닉스 유상증자 + 위험 태그 → 해석·카드 미리보기 펼침 → **[승인]**
- **창① 복귀** → 우측 알림 패널에 SK하이닉스 등장 (5초 내 자동 갱신)
- 멘트: "일반 공시는 즉시, 위험 공시는 사람 검토 후 — 자동화의 속도와 사람의 책임이 여기서 만납니다."

**장면 C — 실시간 알림 폴링** *(30초)*
- 홈에서 **[새 공시 확인]** 클릭 → 오늘 공시가 패널에 (일반=즉시, ⚠️=큐로)
- 멘트: "이 버튼이 하는 일이 폴링입니다 — 5분마다 DART에 '새 공시 있어요?'라고 묻는 방식이고, 발표 통제를 위해 오늘은 수동 트리거로 보여드립니다."
- ⚠️ 주의: [기재정정] 공시는 접수번호가 달라 같은 제목이 여러 건 뜰 수 있음 — "정정 공시도 건별로 잡아냅니다"라고 넘기면 됨.

**장면 D — 가드레일 + 파싱** *(30초)*
- 입력: `그래서 SK하이닉스 지금 팔까?` → 정중한 거절 (검증된 문구 그대로 나옴)
- 입력: `ㅁㄴㅇㄹ` → "질문을 이해하지 못했어요…" (LLM 없이 즉시 — 파싱 노드)
- 멘트: "매매 판단 요청은 거절합니다. 이 거절은 CI가 매 커밋마다 테스트하는 불변입니다."

**클로징** *(20초)* — "게시 5분 내, 근거 붙은 해석, 매매 판단은 사람에게. 오늘 아침의 진짜 공시로 보여드렸습니다. 감사합니다."

## 3. 예상 Q&A

- **Q. 데모가 실패하면?** → 이중 트랙: 리플레이 모드 한 줄 전환(그것도 실제 공시 데이터), 최후엔 백업 영상. "죽는 데모가 없도록 모든 외부 의존에 폴백을 깔았다."
- **Q. 해석이 가끔 어색한데?** → 온프레미스 소형 모델(gemma)의 한계. 그래서 ①사실/해석 분리 구조 ②원문 링크 상시 ③고위험은 HITL로 사람이 확인. 모델 업그레이드는 인터페이스 유지로 교체만 하면 됨.
- **Q. admin 페이지는 아무나 들어가나?** → 화면 분리는 데모용이고 실제 접근제어는 인증(JWT)과 함께 로드맵. 이번 스프린트는 구현 경계를 명시하고 지켰다.
- **Q. 왜 5분 '폴링'인가, 푸시가 아니라?** → DART가 푸시를 제공하지 않아 폴링이 유일한 방법. 5분 주기가 곧 '게시 5분 내' 약속의 근거.
- **Q. Git/AI 협업 사고 있었나?** → main 직접 커밋 사고 1회 → CLAUDE.md에 규칙 명문화 → 이후 PR 14건 무사고. .env.example 실키 유입도 즉시 탐지·제거. "AI에게 안전절차는 말로 시키지 않고 문서와 코드로 고정한다." (상세: 발표_QA노트.md)
- **Q. pgvector 왜 썼나? 실패했으면?** → 벡터+메타데이터+SQL 검증을 한 DB에서, 수업 실습 재활용. 타임박스 2시간 + 인메모리 플랜B를 미리 정해두고 시작했다.
- **Q. CB(전환사채)도 위험한데 왜 즉시 알림인가?** → "맞는 지적. 금융위가 2021·2024년 두 차례 CB 규제를 강화했을 만큼 당국도 고위험으로 본다. 현재 고위험 키워드는 설계서 6.6절의 6종이고, CB·BW는 사모 여부·리픽싱·전환주식비율로 세분화해 올리는 게 로드맵" ([공시_도메인_한장.md](공시_도메인_한장.md) §4)
- **Q. DART 비고의 '유'·'정', IR 배지는?** → 유=유가증권시장본부 소관 / 정=정정으로 대체된 구본(최신 [기재정정]본을 봐야 함) / IR=회사가 등록한 IR홈페이지 링크. 정정마다 접수번호가 새로 발급되므로 폴러가 건별로 잡는 건 DART 구조 그대로.
