## 2. 장별 "설계→구현" 브리지 멘트 (v1 멘트에 덧붙이는 한 줄)

- **S5 (후보 10개)** → "이 중 1번 후보를 실제 코드로 만들었습니다."
- **S8 (아키텍처)** → "이 그림에서 **K8s 상자 하나만 선언이고 나머지 상자는 전부 오늘 돌아갑니다.** 상자=폴더라 저장소를 열면 그대로 확인됩니다."
- **S9 (RAG)** → "설계와 구현의 차이를 말씀드리면 — 설계는 BM25 앙상블이었지만 타임박스 2시간 원칙에 따라 **벡터 단독으로 축소해 완성**했고, 대신 실공시 159청크와 검색거리 0.30~0.36이라는 실측을 확보했습니다. 축소를 숨기지 않는 것도 Delivery라고 생각합니다."
- **S10 (안전장치)** → "이 장의 항목들은 설계가 아니라 **전부 동작 중**이고, CI가 매 커밋마다 이 세 가지(거절·출처·마스킹)를 깨뜨리지 않는지 검사합니다."
- **S11 (Handoff·A2A)** → "이 장은 정직하게 **설계만** 있습니다. 단일 에이전트를 끝까지 완성하는 걸 우선했습니다."
- **S12 (지표)** → "지표는 정의까지 했고 측정 파이프라인은 다음 단계입니다. 단 '출처 포함률 100%'만은 지금도 코드가 강제해서 이미 100%입니다."

## 3. 서비스 철학 멘트 — "개인투자자 필수 5종" (강점 스토리)

"저희가 도메인 분석에서 추린 개인투자자 필수 공시 5종은 ①수주(단일판매·공급계약) ②유상증자 — 특히 **목적이 시설투자냐 채무상환이냐** ③전환사채 ④내부자 매매(임원·주요주주 보고) ⑤분기 실적(공정공시)입니다.
프로토타입은 이 **5종 전용 선별 알림을 구현했습니다** — 폴러가 5종만 추려 알림하고(그 외 일반 공시는 제외, 단 고위험은 카테고리와 무관하게 검토 큐), 알림 카드에 [수주]·[실적] 카테고리 뱃지가 붙으며, **유상증자는 원문에서 자금 사용목적을 읽어 '시설자금/운영자금 목적' 라벨**까지 자동 표기합니다. '호재다'라고 단정하지 않고 '일반적으로 ~로 해석되는 경우가 많다'까지만 — 가드레일은 여기서도 유지됩니다. 내부자 매수/매도 방향 자동 구분만 다음 스텝입니다."
